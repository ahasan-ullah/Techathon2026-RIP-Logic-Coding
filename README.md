# OfficeMonitor

Real-time electrical monitoring for a 3-room office: 2 fans + 3 lights per room (15 devices total across Drawing Room, Work Room 1, Work Room 2). One backend is the single source of truth; a web dashboard and a Discord bot both read and act through it, so both always reflect the same live state.

No physical hardware is involved — device state is generated by a background simulator that flips devices, evaluates alerts, and pushes updates on a timer, so the system always has something live to show.

This README explains how to set up and run the entire project — **backend, dashboard, and bot**.

## Architecture

```
                        ┌─────────────────────────┐
                        │  DeviceSimulatorHostedService │
                        │  (ticks every 15s: toggles     │
                        │   devices, evaluates alerts)   │
                        └──────────────┬──────────────┘
                                       │ writes state via
                                       ▼
                        ┌─────────────────────────┐
                        │        OfficeMonitor API        │
                        │  Controllers + SignalR DeviceHub  │
                        │  (single source of truth, SQL Server) │
                        └──────────┬──────────┬───────────┘
                                   │ REST +    │ REST +
                                   │ SignalR   │ SignalR
                    ┌──────────────▼───┐   ┌───▼──────────────┐
                    │  Web Dashboard      │   │  Discord Bot       │
                    │  (React, this repo) │   │  (.NET, Discord.Net) │
                    └──────────────────┘   └────────────────────┘
```

Both clients hit the same REST endpoints and the same SignalR hub (`/hub/devices`) — there's exactly one backend, exactly one database, one place alert rules live. See [OfficeMonitor/README.md](OfficeMonitor/README.md#real-time-events-signalr) for the full event/endpoint reference, and [docs/system-diagram.png](docs/system-diagram.png) for the full illustrated version.

## Setup & run

Run these **in order** — each piece depends on the last being up first. Use three separate terminals so all three keep running simultaneously.

### 1. Backend (API)

```bash
cd OfficeMonitor
dotnet restore
```

Point the database connection at your SQL Server instance — edit `API/appsettings.json`:

```json
"ConnectionStrings": {
  "DefaultConnection": "Server=localhost\\SQLEXPRESS;Database=OfficeMonitorDB;Trusted_Connection=True;TrustServerCertificate=True;"
}
```

Apply migrations (creates the schema and seeds the 3 rooms + 15 devices):

```bash
dotnet ef database update --project DAL --startup-project API
```

Run it:

```bash
dotnet run --project API
```

**Verify:** open the Swagger UI it prints (e.g. `https://localhost:7081/swagger`) and confirm `GET /api/devices` returns 15 devices. Leave this running — the background simulator starts automatically and begins flipping devices every 15 seconds.

Full reference (all endpoints, SignalR events, alert rules, config keys): [OfficeMonitor/README.md](OfficeMonitor/README.md).

### 2. Web dashboard

```bash
cd "OfficeMonitor Client"
npm install
```

Set `.env.local` to match the port the API actually printed in step 1:

```
VITE_API_BASE_URL=https://localhost:7081/api
VITE_HUB_URL=https://localhost:7081/hub/devices
```

Run it:

```bash
npm run dev
```

**Verify:** open the printed local URL (default `http://localhost:5173`) — you should see live device cards, a power meter, and an alerts panel, all updating on their own every ~15s without a page refresh.

Full reference: [OfficeMonitor Client/README.md](OfficeMonitor%20Client/README.md).

### 3. Discord bot

One-time Discord setup (see [OfficeMonitor/Bot/README.md](OfficeMonitor/Bot/README.md) for the full walkthrough with screenshots-equivalent steps):

1. [discord.com/developers/applications](https://discord.com/developers/applications) → New Application → **Bot** tab → Reset Token, copy it.
2. Same **Bot** tab → enable **Message Content Intent** (without this, the bot can't see command text at all).
3. **OAuth2 → URL Generator** → scope `bot` → permissions Send Messages / Read Message History / View Channels / Embed Links → open the generated URL → authorize it into your server.
4. Developer Mode on in Discord → right-click your alert channel → Copy Channel ID.

Then:

```bash
cd OfficeMonitor/Bot
dotnet user-secrets init
dotnet user-secrets set "Discord:Token" "YOUR_BOT_TOKEN"
dotnet user-secrets set "Discord:AlertChannelId" "YOUR_CHANNEL_ID"
dotnet run
```

**Verify:** the console should print `Gateway Ready`. In your Discord server, type `!status` — you should get an embed back with all 3 rooms. Leave a device on outside 09:00–17:00 (or hit "Run alert check now" on the dashboard) and confirm an alert embed posts to your channel on its own.

Full reference: [OfficeMonitor/Bot/README.md](OfficeMonitor/Bot/README.md).

## Confirming it's all wired together

With all three running, this should hold true:

- Toggling a device on the **dashboard** updates instantly with no refresh, and the **same toggle shows up** if you immediately run `!room <code>` in Discord.
- An alert raised by the backend (after-hours or continuous-usage) appears in the dashboard's **Active Alerts panel** and gets **proactively posted to Discord** within seconds of each other — same event, two views.
- Nobody has to click anything for the numbers to keep moving — the simulator alone keeps the whole system "live."
