# OfficeMonitor

Real-time electrical monitoring for a 3-room office: 2 fans + 3 lights per room (15 devices total across Drawing Room, Work Room 1, Work Room 2). One backend is the single source of truth; a web dashboard and a Discord bot both read and act through it, so both always reflect the same live state.

No physical hardware is involved — device state is generated by a background simulator that flips devices, evaluates alerts, and pushes updates on a timer, so the system always has something live to show.

## Architecture

```
                        ┌─────────────────────────┐
                        │  DeviceSimulatorHostedService │
                        │  (ticks every 15s: toggles     │
                        │   devices, evaluates alerts)   │
                        └──────────────┬──────────────┘
                                       │ writes state via
                                       ▼
                        ┌─────────────────────────┐
                        │        OfficeMonitor API        │
                        │  Controllers + SignalR DeviceHub  │
                        │  (single source of truth, SQL Server) │
                        └──────────┬──────────┬───────────┘
                                   │ REST +    │ REST +
                                   │ SignalR   │ (planned)
                    ┌──────────────▼───┐   ┌───▼──────────────┐
                    │  Web Dashboard      │   │  Discord Bot       │
                    │  (React, this repo) │   │  (not yet built)   │
                    └──────────────────┘   └────────────────────┘
```

Both clients hit the same REST endpoints and the same SignalR hub (`/hub/devices`) — there's exactly one backend, exactly one database, one place alert rules live. See [OfficeMonitor/README.md](OfficeMonitor/README.md#real-time-events-signalr) for the full event/endpoint reference.

## Getting started (full stack)

Run these in order — each piece depends on the last:

### 1. Backend

```bash
cd OfficeMonitor
dotnet restore
# point API/appsettings.json ConnectionStrings:DefaultConnection at your SQL Server
dotnet ef database update --project DAL --startup-project API
dotnet run --project API
```

Full details, including the device inventory, API reference, and alert rules: [OfficeMonitor/README.md](OfficeMonitor/README.md).

### 2. Web dashboard

```bash
cd "OfficeMonitor Client"
npm install
# set VITE_API_BASE_URL / VITE_HUB_URL in .env.local to match the API's actual port
npm run dev
```

Full details: [OfficeMonitor Client/README.md](OfficeMonitor%20Client/README.md).
